## What changed
B.AI now has a working backend. `POST /api/chat` takes a question ("Nasa Pedro Gil Taft ako, papuntang España")
and returns the answer text, the routes for the map, and the disclaimer. Gemini does two jobs only: reading the
question into a small form, and writing the reply from the router's result. Everything still works with no AI:
a simple pattern reader handles "A to B" questions, a From/To form handles the rest, and code-written templates
produce the reply. `npm run try:chat` runs the whole thing in the terminal. 116 tests pass.

## How it was done
1. **Types** (`lib/types.ts`): `Intent` (from `CLAUDE.md`), the API request (message *or* from/to, short history,
   optional location, a picked place) and the response (`kind`, `text`, `plan`/`check`, `choices`, `disclaimer`,
   `writer`, `fallbackReason`).
2. **Gemini client** (`lib/ai/gemini.ts`): JSON mode with a hand-written, flat schema; temperature 0; thinking set to
   MINIMAL (and dropped automatically if the model rejects that setting); 15 s timeout. Every failure becomes
   `AiUnavailable("rate_limited" | "ai_error")`.
3. **Prompts** (`lib/ai/prompts.ts`): the parse prompt never answers; the answer prompt may only use the facts JSON.
   Facts are compacted (no map lines, short stop names) to save tokens.
4. **Pipeline** (`lib/chat/pipeline.ts`): read intent → find places (ambiguous → "Alin dito?" with choices) →
   router → answer. Short replies (off-topic, "Saan ka papunta?", choose a place) use templates: no second AI call.
5. **Answer guard** (`lib/chat/name-check.ts`): the AI text is rejected, and the template used instead, if it names
   any network route the router didn't return, or leaves out the best option's signboard.
6. **Endpoint** (`app/api/chat/route.ts`): zod-validated body, 10 questions/min per visitor, `maxDuration = 30`.
   `next.config.ts` makes sure `network.json` and `landmarks.json` ship with the serverless function.

### Key code
```ts
// 4. Words: Gemini if available and it behaves, else the template.
const text = await deps.ai.writeAnswer({ lang, question, origin, destination, ...result });
const names = checkAnswerNames(text, deps.net, result);
if (names.ok) return done({ ...base, text }, "ai");
fallbackReason = "answer_rejected"; // → plain template, same routes
```
The AI can make the answer friendlier, but it can't make it wrong: if it invents a route, we don't show its text.

## Why it was done this way
- **Flat JSON schema instead of the nested `Intent` union:** simpler schemas get filled correctly more often, and
  code (with zod) builds the real `Intent` from it.
- **Templates for short replies:** saves half the Gemini quota on those questions, and the wording is fixed anyway.
- **Disclaimer as its own field:** the UI's `Disclaimer` component shows it under every answer, so the AI is told not
  to repeat it (a small, deliberate deviation from "append the disclaimer" in `CLAUDE.md`, same result on screen).
- **Alternatives considered:** letting Gemini call the router as a tool (more calls, harder to guarantee "never
  invents routes"); a third-party rate limiter like Upstash (needs an account; overkill here).
- **Trade-offs:** the simple parser only knows a few sentence shapes. Gemini could not be reached from the build
  machine, so the real call is untested here: run `npm run try:chat` once on your PC.

## Concepts to learn from this
- **Structured output / JSON mode**: asking an LLM to fill a JSON schema instead of writing prose, then validating it.
- **Graceful degradation**: every part that can fail (AI, map search) has a plainer path that still answers.
- **Output guardrail**: checking AI text against known facts before showing it.

## How to undo or tweak it
- Prompts: `PARSE_SYSTEM` / `ANSWER_SYSTEM` in `lib/ai/prompts.ts`.
- Thinking level, timeout: `createGeminiClient()` in `lib/ai/gemini.ts`.
- Template wording (Taglish + English): `lib/chat/templates.ts`; disclaimer text: `DISCLAIMER` in `lib/chat/format.ts`.
- Rate limit: `createRateLimiter({ limit: 10, windowMs: 60_000 })` in `app/api/chat/route.ts`.
